# 诗词 App：设计交接与后续要求

更新：2026-09-06。当前为 R3 五页设计原型，已导入 Stitch。已实现的预览与未实现的产品需求见 [当前设计状态](current-design.md)；下文包含后续目标，不代表功能已完成。

决策索引：[Wayfinder 地图](https://github.com/nanfxqs/poetry-ios-app/issues/1)。各决策的完整依据在对应议题，本稿是交给设计工具的执行摘要。

## 目标与视觉方向

个人自用的中国古诗词 iOS App。让人从一首诗进入诗人的人生、人物关系和诗中的地方。首批以李白、杜甫、孟浩然、王维为核心，约30首唐诗为目标，先使用六首种子作品讨论设计。

采用 D「页边入景」作为当前方向，A「画面在上」保留备选。阅读原型：[四个布局与运行说明](https://github.com/nanfxqs/poetry-ios-app/tree/d89e5cd99d2b1b5be16894bd5dc3a9f6631ca3c6/prototypes/reading-layout)。

- 页眉一角出现小幅情景，边缘自然淡出；正文区域保持统一的浅色底。
- 纸白 #FAFAF8、墨灰 #302E2C、暖灰 #756E68，少量胭脂红 #9C4946 强调；规范以 `.stitch/DESIGN.md` 为准。视口 393 × 852，高清截图 1179 × 2556。
- 标题与诗句可用清楚的宋体风格，操作和说明用易读字体；保留系统字号放大的空间。
- 氛围来自少量画面、文字、留白与情境引导。画面不压在诗句下，也不单独占大块首屏。
- 正文和情景静止，仅点选、展开、返回有短过渡；支持减少动态效果。
- 不把地图、生平和星图分别塞进底部导航。

原型图形只用于构图讨论，不是正式资产、历史复原或已经完成的 iOS 界面。

## 页面清单与目标线框（完成范围以当前状态表为准）

### 1. 今日

```text
今日                       声音图标（默认静音）
                            小幅页边情景
作品标题
朝代 · 作者 → 诗人页
诗词正文（长诗自然滚动）
一句可跳过的情境引导
收藏图标
背景／译注／来源（按需展开）
相关作品（少量，注明关联理由）
今日              探索              诗集
```

每日一首，无换一首或连续刷诗入口。当天再次打开仍是同一首。

### 2. 通用作品阅读

复用今日的阅读构图，顶部增加明确返回入口，保留来源页面状态。作品关联地点、作者均能点入；未知地点不显示虚构地点入口。取消收藏时仍留在当前阅读页。

### 3. 探索：地图与结果

```text
搜索标题／诗句／诗人            筛选
地图 | 诗人
已选条件（可移除）             清空
地图标记／区域
──────────────────────────
地点名称 · 写作于此／诗中之地
结果数量                      展开列表
作品卡片 → 阅读
今日              探索              诗集
```

地图与下方结果列表共享筛选条件。点地点后展示当地相关作品，展开列表获得完整结果；地图不自动把用户当前所在城市作为推荐前提，不需要先请求定位权限。

朝代／诗人／意象／情绪／题材分组筛选；组间收窄、组内多选匹配任一项。标签较多时折叠为组，不一次铺满页面。展示“写作于此”和“诗中之地”的清楚说明。

### 4. 诗人页与生平

```text
返回                 诗人姓名 · 朝代
一句简介                         来源
作品 | 生平 | 关系
时间范围／约某年
事件标题 + 短说明
关联作品（有依据时出现）／同期作品
下一节点
```

默认先给人物概要与作品入口。生平按时间串联，不做技术意义上的“链表”展示。不以年龄或年份精确性填满页面；存在不同说法时可展开。

### 5. 局部关系星图

以当前诗人为中心，少量关联人物为邻居。点击人物可高亮相关连线；点击连线出现“赠诗／怀人／留别”等关系说明与证据作品，继续读诗或进入人物页。

朝代是分组或筛选信息。人物姓名优先清楚可读，名称碰撞时减少同时展示数量或展开列表；不让星点闪烁，不持续漂移布局，不用装饰星星冒充人物。

### 6. 诗集

按最近收藏列出整首作品；支持收藏内搜索、取消收藏和进入阅读。提供低干扰的备份状态入口，不把配置和备份错误变成每张诗词卡片的内容。

### 7. 辅助弹层／状态稿（部分待实现）

分组筛选、声音选择与下载、来源与争议、备份与恢复。这些是辅助界面，不增加底部入口。

## 用六首种子作品走通路径

| 种子 | 设计中要检验的情况 |
| --- | --- |
| 黄鹤楼送孟浩然之广陵 | 从阅读进入孟浩然与诗中地点；标记不冒充精确创作坐标 |
| 赠孟浩然 | 点关系后看到具体赠诗依据 |
| 春日忆李白 | “怀人”关系；渭北与江东按区域表达，避免精确人物定位 |
| 送元二使安西 | 区分送别场景与远行方向，不将目的地误标为写作地 |
| 留别王侍御维 | 孟浩然到王维的作品关联；未核定地点时不强行落点 |
| 过故人庄 | 没有已核定精确地点或具名故人，仍有完整阅读与标签体验 |

来源与核查限制见 [种子样本](../research/first-content-sample.md)。生平事件在资料核定前使用明确标注的结构占位，不能生成看似真实的编年记录。

## 后续实现必须覆盖的状态（并非全部已有）

| 状态 | 呈现与操作 |
| --- | --- |
| 长标题、长诗、大字号 | 标题换行、正文滚动，不截断诗句，不靠缩小字号塞满一屏 |
| 空诗集 | 简短说明，提供“去读今日诗词” |
| 筛选无结果 | 保留条件，提供清空或移除某个条件；无图点不等于无可读作品 |
| 地图底图不可用 | 显示本地地点列表和作品卡片，保留筛选 |
| 地点未知 | 仍可阅读与收藏，来源区说明尚未核定 |
| 约年、区域或存在争议 | 主页面简明标注，详情看来源和不同说法 |
| 生平节点没有作品 | 保留事件卡片；不显示假诗词链接 |
| 人物没有已核定关系 | 简单文字说明与作品入口，不生成空转的装饰星图 |
| 返回探索／阅读 | 恢复地图状态、筛选、列表及阅读位置 |
| 声音未下载 | 显示下载操作；离线提示稍后下载，正文正常阅读 |
| 待备份 | 收藏已本地保存，显示待备份及可重试入口 |
| 备份成功 | 备份页显示最近成功时间，不反复弹窗打断阅读 |
| 内容更新失败 | 保留旧内容，辅助区域提供重试，不覆盖阅读页 |
| 恢复收藏 | 用户主动操作，说明将取回哪份备份；新安装的空库不自动覆盖旧备份 |

## 声音与画面资产要求

环境声按情景复用，首版建议水声、风声、雨声三类，不做逐诗配曲。默认关闭，主动播放，可停止；优先同时只播放一个声音。短循环有平滑接缝，不搭建在线音乐库，不做自动朗读。

静态页边画面建议四类：江水远帆、林间风影、田园山色、月夜天光。它们表达意境，不作为具体地点的历史复原。不同诗词可以复用同类构图，不必为每首诗创建独立图片。

素材优先使用自行绘制的简洁图形或明确可再利用的公开资产。使用时逐件记录来源与许可；没有资产时用清楚标注的占位，不从网页随意搬运。候选来源见[媒体调研](../research/poetry-media-sources.md)，设计阶段只提交资产清单，不要求生成正式素材。

## 本地推荐规则

用户已选择人工编排顺序、本地每日轮换；同一天保持不变。实施建议：首次使用确定本地起始日，按自然日推进，当天选定作品保存下来，时区变化或内容更新不在当天悄悄换诗。走完编排后循环。

相关作品按共同意象或题材挑选，排除当前作品，最多显示三首，展示“同写送别”等简短理由；没有匹配时省略这一段。原型阶段使用确定性示例，不需要 AI 推荐服务。

## 首轮 Stitch 交付顺序

1. 先设计今日／通用阅读、探索地图、诗人页、局部关系星图、诗集五个核心构图；今日与通用阅读共用布局规则。
2. 在选定构图上补充分组筛选、生平展开、声音与备份等状态。
3. 按种子样本和状态表检查主路径与返回路径，修正可读性和密度。

验收重点：首屏能读到正文；画面不抢占空间或盖住诗句；三个底部入口固定；地点与关系的含义清楚；离线与资料不足仍能继续阅读；小字、长诗与中文名称可读。

本稿不假定 Stitch 直接产出可构建的 SwiftUI。最终设计应交付页面、状态、字体色彩间距规则和素材说明，随后在原生工程落实。

用户手动启用 Stitch MCP 与配套技能后才调用；启用前明确告知“下一步开始调用 Stitch”。
